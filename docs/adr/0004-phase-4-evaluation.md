# ADR 0004 — Phase 4 evaluation harness and regression gate

Date: 2026-11-20 · Status: proposed (pending the laptop run, runlogs/phase4)

## Context

Phases 1–3 were verified with scripted spot checks: a dozen lookups, a few
mappings, three full answers. They show that a feature works, not how well the
system answers the questions people ask, which change helped, or whether a later
change made retrieval worse. Phase 4 adds a measured, repeatable evaluation and a
gate that blocks regressions in pull requests.

## Decisions

1. **A golden set written for this corpus, checked against it.** 200 items in
   seven categories (`eval/datasets/golden_v1.jsonl`, generated by
   `build_golden_v1.py` so the items are reviewable as code). Gold is expressed
   as provision labels (`BNS s.103`, `Constitution Art.21`, `BNSS Schedule
   First`) and judgment doc_ids — stable across re-chunking, unlike chunk ids.
   Before any run, every item is validated against the live index: its gold
   provisions must exist and its key phrases must occur in their text. Invalid
   items are excluded and listed in the report. The items were written by the
   assistant and machine-validated, not reviewed by a lawyer; the report says so.
2. **Dev/test split by hash, test locked by checksum.** `sha256(category:id)`
   puts ~60% of items in dev. Adding items never moves existing ones. After the
   first clean laptop run, `eval/datasets/golden_v1.lock.json` records the test
   items' checksum; the loader refuses an edited test split. Tuning (thresholds,
   prompts, budgets) uses dev only; test is reported once per release.
3. **Provision-level retrieval metrics.** The passages the model would see are
   reduced to provision keys in rank order (pieces of one section count once):
   Hit@1/5, Recall@8, MRR@10, nDCG@10 (binary). These are what matter for a
   legal answer — the right section in the context — and are deterministic.
4. **Answer metrics without a judge first.** Citation validity (markers the
   verifier had to remove), gold provision cited, key phrases present, correct
   code applied, verification passed, abstention precision/recall, refusal
   recall, injection resistance (forbidden output absent), time to first token.
   All are computed from the SSE events the UI receives.
5. **Model-judged metrics are optional and not RAGAS.** Faithfulness, answer
   relevancy, citation support, context precision and context recall follow the
   RAGAS definitions but are computed by `lexai.evaluation.judge` with two
   prompts per item. The `ragas` package was not added: it pulls LangChain, which
   the project deliberately removed, and its prompts assume a strong judge. A
   judge must be stronger than the 7B generator (grading itself is unreliable),
   so it runs only when `LEXAI_EVAL_JUDGE_BASE_URL/_MODEL` point at one; reports
   state "not run" otherwise.
6. **Ablations through settings, not code forks.** `retrieval.mode`
   (hybrid/dense/bm25) and `query.routing_enabled` were added so the harness can
   measure each component's contribution with the production code path. HyDE and
   the reranker are existing switches.
7. **Offline regression gate in CI.** `export-fixture` (run where the real index
   and models are) saves every chunk's payload, dense vector (float16) and BM25
   vector, plus, for a 50-item dev smoke set, the standalone query (follow-ups
   rewritten by the real model) and its embedding. In CI the fixture is loaded
   into an in-memory Qdrant and the smoke set runs through the real router,
   correspondence and context assembly with a lookup-table embedder. The PR fails
   if Recall@8 or MRR@10 falls more than 0.02 below `eval/baselines/main.json`.
   Changes to the embedder, chunker or BM25 tokenizer need a new fixture (a BM25
   version mismatch is refused). The planted-regression check (routing off must
   fail the gate) is part of the test suite.
8. **Load testing at laptop scale.** `scripts/load_test.py` measures search
   latency at 1/4/8 concurrent clients and answer latency at 1/2. Many-user tests
   (Locust) need the GPU server and belong to the deployment phase.

9. **Follow-up rewrites are checked, not trusted (from run 1).** The 7B
   rewrite regularly added old-code sections or invented acts, and the router
   pinned them. A rewrite may now name only acts the user named and sections
   that appear in the conversation; otherwise the previous user question and
   the follow-up are searched verbatim. An explicit era in the user's own words
   ("...of the new code?") outranks the rewrite.
10. **Prompt `answer_v4`, selectable (from run 1).** v3 answers often cited only
   in the "Provisions:" footer. v4 adds a two-sentence worked example of inline
   citation (~140 tokens) and tells the model to answer only the legal part of a
   message that tries to override its rules. `LEXAI_LLM_PROMPT_VERSION` selects
   the template (v3 kept for comparison); the version is part of the cache key
   and of every result. An abstention is no longer flagged "no citations".

## Consequences

- Every PR is checked for retrieval regressions without Ollama, a GPU or the
  on-disk index. The fixture (~10–20 MB) is committed and re-exported when the
  corpus or embedder changes.
- Numbers are tied to a commit (`eval/reports/<commit>/`), with the settings
  that produced them.
- The sandbox used to develop the harness has fake vectors, so its numbers are
  meaningless; only laptop numbers are reported.
